# LOXA RPG → Telegram

Бот-уведомитель для [loxa-rpg.vercel.app](https://loxa-rpg.vercel.app/ru/blog): сам проверяет сайт,
и когда вы публикуете:

- **новую статью блога** → отправляет в Telegram-канал **полный текст статьи в markdown-разметке**
  (заголовки, жирный/курсив, списки, ссылки, код — всё превращается в нативное форматирование Telegram);
- **новую главу книги** → отправляет **короткое сообщение**: «вышла новая глава», номер + название главы и ссылку.

Работает **бесплатно и без вашего участия**: раз в N минут проверяет сайт, отправляет новое, дубликаты не шлёт.

```
loxa-rpg.vercel.app            этот проект                 Telegram
┌─────────────────┐   HTML   ┌──────────────────┐  Bot API  ┌─────────────┐
│ /ru/blog        │ ───────► │ scraper → markdown│ ────────► │ ваш канал   │
│ /ru/book        │          │ formatter → HTML  │           │ @loxa_...   │
│ /ru/blog/<slug> │          │ state.json (анти- │           └─────────────┘
└─────────────────┘          │ дубли)            │
                             └──────────────────┘
```

## 0. Что уже проверено на вашем сайте

Проект настроен именно под ваш сайт и протестирован на живых данных (10 сентября 2026):

| Раздел | Что видит бот |
|---|---|
| `/ru/blog` | «Нововведения. Реально.» (10 сентября), «Об состоянии проекта», «Здравствуйте!» |
| `/ru/book` | Глава 01 «Братья по оружию», Глава 02 «Тень Пантеры», Глава 03 «Борский крылатый флот» |

Сообщение для блога выглядит так (в Telegram — с жирным, курсивом и ссылками):

```

Нововведения. Реально.
10 сентября 2026 г. · 1 мин чтения

На каком этапе сейчас проект?

Уже почти готова первая локация...        ← слово «почти» жирное
...
Ваша команда 6-7 Corp.

🔗 Открыть на сайте
```

Сообщение для главы книги:

```
📖 Вышла новая глава книги!

Глава 03 — Борский крылатый флот
10 сентября 2026 г. · 12 мин чтения
67 Подвигов Петуха.

🔗 Читать главу
```

Если статья длиннее лимита Telegram (4096 символов на сообщение) — она автоматически
разбивается на части `(1/3)`, `(2/3)`, `(3/3)`, а если частей больше, чем `MAX_MESSAGE_PARTS` —
остаток приходит **файлом `.md`**, чтобы точно ничего не потерялось.

## 1. Быстрый старт: 5 шагов

### Шаг 1. Создайте бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Имя: например `LOXA RPG Notifier`, username: например `loxa_rpg_bot` (должен быть свободен).
3. Скопируйте токен вида `1234567890:AAH...` — это `TELEGRAM_BOT_TOKEN`.

### Шаг 2. Добавьте бота в канал и узнайте chat_id

1. В вашем канале: **Управление → Администраторы → Добавить администратора** → выберите бота.
   **Обязательно дайте право «Публикация сообщений»** — без него бот не сможет писать.
2. Узнайте `chat_id` канала. Самый простой способ:
   - поставьте в канале одну тестовую запись (любую);
   - откройте в браузере `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`;
   - найдите фрагмент `"channel_post":{"chat":{"id":-1001234567890` — это и есть chat_id
     (обязательно с минусом и префиксом `-100`).
3. Альтернатива: если канал публичный, можно просто указать его `@username`, например `@loxa_rpg`.
   Для приватного канала нужен числовой id из `getUpdates`.

### Шаг 3. Запустите локально и проверьте

```bash
cd loxa-notifier
python3 -m venv .venv
source .venv/bin/activate           # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
nano .env                           # вставьте TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
```

Проверка (бот отправит в канал приветственное сообщение):

```bash
python bot.py test
```

Посмотреть, что бот видит на сайте, ничего не отправляя:

```bash
python bot.py discover              # список статей и глав
python bot.py preview               # как будет выглядеть свежий пост
python bot.py preview panther-history
python bot.py check --dry-run       # полный прогон без отправки
```

### Шаг 4. Запомните существующий контент

Чтобы бот не «вывалил» в канал все уже опубликованные статьи при первом запуске:

```bash
python bot.py seed
```

Теперь всё, что уже есть на сайте, помечено как известное — и бот будет отправлять **только новое**.

> Если наоборот хочется, чтобы первый запуск разослал вообще всё — используйте
> `python bot.py check --force` или `python bot.py check --announce-baseline`.

### Шаг 5. Поставьте на бесплатный «вечный» запуск

Локально бот не работает, когда компьютер выключен. Поэтому — любой из вариантов ниже.
**Рекомендую вариант A** (GitHub Actions): бесплатно, без карты, ничего держать не надо.

## 2. Бесплатный хостинг: что выбрать

| Вариант | Цена | Интервал проверки | Карта нужна | Плюсы | Минусы |
|---|---|---|---|---|---|
| **A. GitHub Actions** ⭐ | 0 ₽ (публичный репо — минуты не ограничены) | от 5 мин | нет | 0 настройки сервера, логи, ручной запуск кнопкой | cron может опаздывать на 5–20 мин; приватный репо — 2000 мин/мес |
| **B. Oracle Cloud Always Free VM** | 0 ₽ навсегда | от 1 мин | да (верификация) | настоящий 24/7 сервер, полный контроль | нужно один раз настроить Linux-сервер |
| **C. Docker на бесплатном хостинге** | 0 ₽/пробные кредиты | от 1 мин | обычно да | просто `docker compose up` | бесплатные тарифы часто «усыпляют» контейнер |
| **D. Vercel Cron** | 0 ₽ | **1 раз в сутки** (Hobby) | нет | вы уже в Vercel | не подходит для «сразу после публикации» без внешнего триггера |

### Вариант A (рекомендую): GitHub Actions

Вы получаете бесплатный планировщик каждые 10 минут, логи каждого запуска и кнопку «запустить сейчас».

**A1. Создайте репозиторий и залейте проект**

```bash
cd loxa-notifier
git init
git add .
git commit -m "loxa notifier"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/loxa-notifier.git
git push -u origin main
```

Репозиторий можно сделать **публичным** (код секретов не содержит — токен хранится в Secrets) —
тогда минуты Actions не ограничены, и можно проверять каждые 10 минут бесплатно.
Для **приватного** репозитория бесплатно 2000 минут в месяц, поэтому интервал лучше ставить `*/30` или `0 * * * *`:

| Интервал | Запусков в день | Примерный расход в месяц | Приватный репо (2000 мин) |
|---|---|---|---|
| `*/10` (каждые 10 мин) | 144 | ~3600 мин | ❌ не влезает |
| `*/15` | 96 | ~2400 мин | ❌ не влезает |
| `*/30` | 48 | ~1200 мин | ✅ влезает |
| `0 * * * *` (раз в час) | 24 | ~600 мин | ✅ влезает с запасом |

**A2. Добавьте секреты**

GitHub → ваш репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | `@loxa_rpg` или `-1001234567890` |

**A3. Включите Actions**

Вкладка **Actions** → включите workflows. Готовый файл `.github/workflows/notify.yml` уже в проекте.

**A4. Первый запуск вручную**

**Actions → LOXA → Telegram → Run workflow**. Первый запуск **только запоминает** существующие материалы
(в канал ничего не придёт — это защита от спама). Хотите сразу проверить отправку —
поставьте галочку `announce_baseline` (отправит всё, что сейчас есть на сайте) или сначала сделайте
локально `python bot.py seed`, а потом пушьте.

**A5. Измените интервал (по желанию)**

В `.github/workflows/notify.yml`:

```yaml
on:
  schedule:
    - cron: "*/10 * * * *"   # ← измените на "*/30 * * * *" или "0 * * * *"
```

Важное: время в cron — **UTC**, минимум у GitHub — 5 минут, и запуск может «опоздать» на 5–20 минут.
Для новостей это нормально. Ещё нюанс: GitHub отключает расписания в неактивных (>60 дней) репозиториях —
у нас каждый запуск коммитит `state.json`, так что репозиторий всегда активен.

Как это выглядит в логах Actions:

```
✅ Отправлено — статей: 1, глав: 1 (сообщений: 2)
```

Файл `state.json` коммитится обратно в репозиторий — именно он не даёт отправлять дубликаты между запусками.

### Вариант B: Oracle Cloud Always Free (настоящий 24/7)

Полностью бесплатный навсегда виртуальный сервер. Идеально, если хочется проверку каждые 5 минут
и никакой зависимости от GitHub-планировщика.

1. Зарегистрируйтесь на [cloud.oracle.com](https://www.oracle.com/cloud/free/) (нужна карта для верификации,
   списаний на Always Free ресурсах нет).
2. **Create Instance**: образ Ubuntu 24.04, форма `VM.Standard.E2.1.Micro` (Always Free) —
   её хватит с огромным запасом. Скачайте SSH-ключ, создайте инстанс.
3. Откройте порт для SSH (`22` уже открыт) и подключитесь:
   ```bash
   chmod 600 ssh-key.key
   ssh -i ssh-key.key ubuntu@<IP-АДРЕС>
   ```
4. Одна команда для установки (клонирует репо, ставит venv, создаёт systemd-таймер каждые 5 минут):
   ```bash
   curl -fsSL https://raw.githubusercontent.com/ВАШ_ЛОГИН/loxa-notifier/main/deploy/install-on-server.sh \
     | bash -s -- https://github.com/ВАШ_ЛОГИН/loxa-notifier.git
   ```
   Либо, если репозиторий приватный — сначала `git clone`, потом `sudo bash deploy/install-on-server.sh <url>`.
5. Впишите токен и канал:
   ```bash
   nano /opt/loxa-notifier/.env
   cd /opt/loxa-notifier && ./.venv/bin/python bot.py test   # проверка связи
   cd /opt/loxa-notifier && ./.venv/bin/python bot.py seed   # запомнить существующее
   ```
6. Управление:
   ```bash
   systemctl list-timers loxa-notifier.timer     # когда следующий запуск
   systemctl start loxa-notifier.service         # запустить сейчас
   journalctl -u loxa-notifier -f                # живые логи
   ```

> Честное предупреждение: Oracle иногда «забирает» простаивающие Always Free инстансы.
> Наш бот почти не грузит CPU, поэтому такое может случиться. Восстановление — 10 минут
> (создать инстанс заново и повторить шаг 4), весь код и настройки у вас в git.

Альтернатива внутри варианта B — тот же сервер, но через Docker в режиме «постоянно в фоне»:

```bash
git clone https://github.com/ВАШ_ЛОГИН/loxa-notifier.git /opt/loxa-notifier && cd /opt/loxa-notifier
cp .env.example .env && nano .env
sudo docker compose --profile always-on up -d scheduler
sudo docker compose logs -f scheduler
```

### Вариант C: любой хостинг с Docker

В проекте есть `Dockerfile` и `docker-compose.yml`, так что подойдёт Fly.io, Railway, Koyeb, VPS и т.п.

```bash
docker compose run --rm notifier                                   # разовая проверка (для cron хоста)
docker compose --profile always-on up -d scheduler                 # проверка каждые 10 минут
```

На хостингах с бесплатным тарифом держите в голове: бесплатные инстансы часто «засыпают» после
простоя (Railway даёт стартовые кредиты, Koyeb умеет будить сервис по запросу) — режим
`always-on` там работает с оговорками. Если нужен именно 24/7 — вариант A или B надёжнее.

### Вариант D: Vercel Hobby + внешний триггер

Вы уже в Vercel, и у Hobby-плана есть Cron Jobs — **но только один запуск в сутки**.
Если хочется остаться целиком в Vercel: добавьте в проект сайта route `/api/loxa-notify`
(в нём вызывайте логику этого бота) и повесьте `vercel.json`:

```json
{ "crons": [{ "path": "/api/loxa-notify", "schedule": "0 9 * * *" }] }
```

Для частых проверок внешний планировщик (например, [cron-job.org](https://cron-job.org), бесплатно)
дёргает этот URL каждые 5–10 минут — Vercel-роуты принимают запросы с любой частотой, ограничение
касается только встроенного планировщика. Это рабочий, но более «самодельный» путь: проще взять вариант A.

## 3. Настройки (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | **обязательно**, токен от @BotFather |
| `TELEGRAM_CHAT_ID` | — | **обязательно**, `@username` канала или `-100...`; можно несколько через запятую |
| `PARSE_MODE` | `HTML` | формат разметки сообщений (`HTML` надёжнее, `MarkdownV2` — если хочется) |
| `SITE_BASE_URL` | `https://loxa-rpg.vercel.app` | адрес сайта |
| `LOCALE` | `ru` | локаль, из которой берём контент (`ru`/`en`) |
| `WATCH_BLOG` / `WATCH_BOOK` | `true` | что отслеживать |
| `MESSAGE_MAX_CHARS` | `3800` | лимит длины одной части (максимум Telegram — 4096) |
| `MAX_MESSAGE_PARTS` | `4` | максимум частей на статью |
| `SEND_MARKDOWN_FILE` | `true` | прикладывать `.md`-файл, если не влезло |
| `DISABLE_LINK_PREVIEW_BLOG` | `true` | отключить превью ссылки под статьёй |
| `DISABLE_LINK_PREVIEW_BOOK` | `false` | для глав превью оставляем (красиво) |
| `STATE_FILE` | `state.json` | где хранится память бота |
| `HTTP_TIMEOUT` / `HTTP_RETRIES` | `25` / `3` | таймаут и повторы запросов к сайту |

### Свои шаблоны сообщений

Хочется другой текст — переопределите шаблон в `.env` (переносы строк пишутся как `\n`):

```env
POST_TEMPLATE_BOOK=🔥 <b>Новая глава!</b>\n\n<b>{heading}</b>\n{meta}\n{summary}\n\n🔗 <a href="{url}">Читать</a>
```

Плейсхолдеры: для статьи — `{title} {meta} {body} {url} {summary} {date} {reading_time}`;
для главы — `{heading} {chapter} {title} {meta} {summary} {url} {date} {reading_time}`.
Текст статьи (`{body}`) — это markdown прямо с вашего сайта; он автоматически конвертируется
в форматирование Telegram.

## 4. Команды

```bash
python bot.py check                 # основная: проверить сайт и отправить новое
python bot.py check --dry-run       # то же, но без отправки (для отладки)
python bot.py check --only blog     # только блог
python bot.py check --limit 1       # не больше одного материала за запуск
python bot.py check --force         # игнорировать память: переслать всё найденное
python bot.py check --announce-baseline   # первый запуск: разослать и существующие материалы
python bot.py test                  # проверить токен и прислать тестовое сообщение
python bot.py preview [slug]        # как будет выглядеть сообщение
python bot.py seed                  # запомнить текущее содержимое, не отправляя
python bot.py export                # выгрузить весь сайт в Markdown (export/)
python bot.py discover              # что бот видит на сайте
python -m unittest discover -s tests -v    # тесты (17 штук, работают без сети)
```

`make help` показывает то же самое короткими командами.

## 5. Как это устроено внутри (на случай доработок)

| Файл | Отвечает за |
|---|---|
| `src/scraper.py` | загрузка и разбор `/ru/blog`, `/ru/book`, страниц материалов, `sitemap.xml` (как резерв) |
| `src/htmlmd.py` | HTML → Markdown (заголовки, списки, цитаты, код, таблицы, ссылки, картинки) |
| `src/formatter.py` | Markdown → Telegram HTML/MarkdownV2, шаблоны, безопасная разбивка на части |
| `src/telegram.py` | Bot API: отправка сообщений и файлов, ретраи, обработка 429 |
| `src/state.py` | `state.json` — что уже отправлено |
| `src/notifier.py` | сценарий: сбор → сравнение → отправка |
| `src/cli.py` | команды `check/test/preview/seed/export/discover` |
| `tests/` | 17 тестов на сохранённых HTML-фикстурах (сеть не нужна) |

Полезные детали:

- **Анти-дубликаты.** Новым считается материал, чей путь (`/ru/blog/innovations-1`) ещё не встречался
  в `state.json`. Первый запуск запоминает всё существующее, поэтому спама не будет.
- **Несколько статей за один запуск.** Если вышло сразу три статьи, бот отправит полный текст только
  у самой свежей, а у остальных — короткое сообщение со ссылкой (чтобы канал не «взорвался»).
  Главы книги всегда идут коротким сообщением — как вы и просили.
- **Обновлённая старая статья** повторно не отправляется (путь уже известен). Если нужно переслать —
  `python bot.py check --force` или удалите запись из `state.json`.
- **Названия частей.** Все настройки меняются в одном месте — `.env`, переписывать код не нужно.
- **Смена разметки сайта.** Если сайт сильно переделают, обновите фикстуры и прогоните тесты:
  `python tools/refresh_fixtures.py && python -m unittest discover -s tests -v`.
  Если что-то отвалилось — правится в `src/scraper.py` (селекторы `.zmd` и ссылки в листингах).

## 6. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Bad Request: chat not found` | Бот не добавлен в канал или неверный `chat_id`. Добавьте бота админом, для приватного канала возьмите id из `getUpdates` (с минусом) |
| `Forbidden: bot is not a member...` | Бот не админ канала или нет права «Публикация сообщений» |
| `Not enough rights to send text messages` | То же: дайте право публикации |
| В канал ничего не приходит, в логах `Новых материалов нет` | Всё уже отправлено ранее. Проверьте `python bot.py discover`, затем `python bot.py check --force --dry-run` |
| Первый запуск ничего не отправил | Так и задумано: он запоминает существующее. Нужна рассылка — `--announce-baseline` |
| Сообщение пришло с «сырыми» `**звёздочками**` | Проверьте `PARSE_MODE=HTML` в `.env` (это значение по умолчанию) |
| Telegram вернул `429 Too Many Requests` | Бот сам ждёт указанное время и повторяет; если часто — увеличьте интервал проверки |
| GitHub Actions не запускается по расписанию | Расписания работают только на ветке по умолчанию (`main`), минимум 5 минут, могут опаздывать. Нажмите **Run workflow** для ручной проверки |
| Дубликаты сообщений в GitHub Actions | `state.json` не коммитится: проверьте, что у workflow есть `permissions: contents: write` и нет защиты ветки от записи |
| Статья длиннее лимита | Она разобьётся на части, остаток придёт `.md`-файлом. Можно увеличить `MAX_MESSAGE_PARTS` |
| Сайт отдаёт 404 на статью | Бот пропустит её и напишет об ошибке в лог, остальные материалы уйдут нормально |

Диагностика с максимальной подробностью:

```bash
python bot.py check --dry-run --verbose
```
